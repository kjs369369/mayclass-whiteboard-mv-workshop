# STEP 02 · 곡 구조 측정과 막 경계

이 단계에서 정하는 것은 **막을 몇 개로 나누고, 각 막이 몇 초부터 몇 초까지인가**
입니다. 뒤의 모든 단계가 이 숫자에 매달려 있으니 추정하지 말고 측정합니다.

## 왜 도구의 제안을 쓰지 않는가

레포에는 `scripts/parse_srt.py`가 있고, SRT를 받아 25~35초 단위로 막을 제안합니다.

```bash
PYTHONUTF8=1 python scripts/parse_srt.py \
  assets/whiteboard/mayclass-dreamers/dreamers.srt \
  --target-sec 30 --min-sec 25 --max-sec 35
```

돌려 보면 결과가 나옵니다. 하지만 **이 제안을 그대로 쓰면 안 됩니다.**
알고리즘이 자막 길이만 보기 때문에 음악을 모릅니다.

Dreamers에서 실제로 이랬습니다.

- 1막을 **6초부터** 시작하겠다고 제안 → 인트로 6초가 영상에서 사라집니다
- 3막을 **16.76초**로 잘랐습니다 → 자기가 정한 최소 기준(25초)마저 어깁니다

`parse_srt.py`는 "자막이 몇 개고 대략 어디서 끊기는지" 훑어볼 때만 씁니다.
막 경계는 곡에서 직접 뽑습니다. (함정노트 G절)

## 곡 에너지 측정

1초 단위 RMS(제곱평균제곱근) 에너지를 뽑습니다. 소리가 실제로 커지고
작아지는 지점이 곡의 구조입니다.

```bash
PYTHONUTF8=1 .venv/Scripts/python - <<'PY'
import subprocess, numpy as np
SONG = "assets/whiteboard/aiclab-shine/shine-cut.mp3"   # ← 자기 음원 경로

raw = subprocess.run(
    ["ffmpeg", "-v", "quiet", "-i", SONG, "-f", "s16le", "-ac", "1", "-ar", "8000", "-"],
    capture_output=True).stdout
x = np.frombuffer(raw, "<i2").astype(np.float32) / 32768
print(f"길이 {len(x)/8000:.2f}초")
for s in range(len(x) // 8000):
    rms = np.sqrt((x[s*8000:(s+1)*8000] ** 2).mean())
    print(f"{s:3d}s  {rms:.3f}  {'#' * int(rms * 120)}")
PY
```

막대가 눈으로 보이니 구조가 바로 읽힙니다. Dreamers 측정 결과가 이랬습니다.

| 구간 | RMS | 해석 |
| --- | --- | --- |
| 0–14초 | 0.05 → 0.14 | 인트로, 후크 |
| 15–33초 | 0.11 → 0.17 | 1절 |
| 34–41초 | 0.13 → 0.20 | 빌드업 |
| 42–62초 | 0.18 → 0.25 | 코러스 (42초 최고점 0.253) |
| 63–65초 | 0.16 | 브릿지, 골짜기 |
| 66–81초 | 0.19 → 0.25 | 후반 코러스 |
| 82–87초 | 0.13 → 0.017 | 아웃트로 페이드 |

## 막 경계 잡는 기준

두 종류의 지점을 찾습니다.

1. **급상승** — 앞 초보다 확 뛰는 곳. Dreamers는 33초 `0.131` → 34초 `0.194`.
2. **골짜기 뒤 반등** — 잠깐 죽었다가 다시 올라오는 곳. 63~65초 골짜기 후
   66초 `0.240`.

이 지점들이 곡이 실제로 꺾이는 곳입니다. 여기를 막 경계로 씁니다.

Dreamers 최종 결과:

| 막 | 시간 | `sceneDurationMs` | 자막 cue | 제목 |
| --- | --- | --- | --- | --- |
| 1 | 0–34초 | 34000 | 1–6 | 한 걸음씩 하늘로 |
| 2 | 34–65초 | 31000 | 7–14 | 밤과 비를 지나 |
| 3 | 65–87.76초 | 22760 | 15–18 | 하나가 되어 빛남 |

## 반드시 확인할 것

**막 길이의 합 = 음원 길이.**

```
34.00 + 31.00 + 22.76 = 87.76초 ✓
```

여기서 어긋나면 STEP 09의 먹싱에서 영상과 음악이 밀립니다. 렌더할 때
`--total-ms`로 각 막의 길이를 강제하므로, 지금 정한 숫자가 그대로 결과가 됩니다.

## 막 개수 감각

| 곡 길이 | 막 개수 | 근거 |
| --- | --- | --- |
| 60~90초 | 3막 | 막당 25~35초. 이 교재의 두 사례 |
| 90~150초 | 4~5막 | |
| 3분 | 5~6막 | 렌더 시간이 막당 3분이므로 18분 |

막이 너무 짧으면 그림 하나에 담을 사건이 부족하고, 너무 길면 한 장면을 40초
넘게 보게 되어 지루합니다. **25~35초를 벗어나면 다시 나눕니다.**

## 기록해 두기

STEP 05·07·08에서 계속 참조합니다. 이렇게 적어두세요.

```
막1  0.00 – 34.00초   34000ms

```

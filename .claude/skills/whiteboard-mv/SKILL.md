# 화이트보드 손그림 뮤직비디오

노래를 **미색 종이(`#F5EBD7`) 위에 펜이 실제로 선을 그어나가는** 16:9 애니메이션으로
만든다. 곡을 3막 안팎으로 나누고, 막마다 선화 한 장을 생성한 뒤, 그 선화를
영역으로 쪼개 **가사의 사건 순서대로** 하나씩 그려낸다. 마지막에 카메라 무빙을
얹고 음원을 먹싱한다.

가사는 화면에 띄우지 않는다. 자막(SRT)은 **그리는 순서와 시점을 정하는 용도**로만 쓴다.

완성 사례: `assets/whiteboard/mayclass-dreamers/` (87.76초), `assets/whiteboard/aiclab-shine/` (78.3초).
막히면 이 두 폴더의 `annotation.json`과 `kenburns_and_mux.sh`를 그대로 참고한다.

## 확인 관문 (반드시 지킨다)

렌더가 막당 3분씩 걸린다. 뒤에서 되돌리면 손해가 크므로 **두 곳에서 멈추고 확인을 받는다.**

1. **선화 3장을 보여준 직후** — 다음 단계(annotation 작성)로 넘어가지 않는다.
2. **영역 검사도를 보여준 직후** — 렌더를 시작하지 않는다.

"사용자가 반대하지 않았다", "앞서 포괄적으로 승인했다"를 확인으로 취급하지 않는다.
수정 요청이 오면 그 단계만 다시 하고 또 확인을 받는다.

`annotation.json`을 만든 직후 **예뷰대(`assets/preview.html`)를 자동으로 열고**
해당 장면 폴더를 불러오는 것은 3단계의 산출물이므로 별도 확인이 필요 없다.

## 시각 규범 (선화 생성 프롬프트에 그대로 넣는다)

- 미색 종이 배경 `#F5EBD7`, 짙은 회색 스케치 선. 극단순 손그림, 여백 충분히.
- 강조색은 **빨강·주황·파랑만, 소량**. 다른 강조색·고채도 금지.
- **화면 안에 문자·숫자·라벨 절대 금지.** 브랜드명조차 글자로 쓰지 않고 기호로 표현한다.
- 사실적 묘사·사진 질감·3D·복잡한 배경·밀집 장식 금지.
- **"single clean flat uniform tone, no stains, no cracks, no vignette, no aged look,
  no paper grain"을 반드시 명시한다.** 이걸 빼면 종이 얼룩이 마지막 프레임에
  한꺼번에 튀어나온다(모서리 표준편차 4.6~5.3 → 명시하면 0.00).
- **안전영역**: 켄번즈가 가장자리를 잘라낸다. 주요 요소를 **중앙 80% 안에** 배치하라고
  프롬프트에 명시한다.
- 주체 사이에 여백을 충분히 둔다. 붙어 있으면 영역으로 쪼갤 수 없다.

## 절차

### 1. 곡 구조를 측정한다

`parse_srt.py`의 분경 제안을 **쓰지 않는다.** 그 알고리즘은 자막 길이만 보고 30초에
맞추므로 음악을 모른다. 대신 1초 단위 RMS 에너지의 전이점을 막 경계로 쓴다.

```bash
python - <<'PY'
import subprocess, numpy as np
raw = subprocess.run(["ffmpeg","-v","quiet","-i","<음원.mp3>","-f","s16le","-ac","1","-ar","8000","-"],
                     capture_output=True).stdout
x = np.frombuffer(raw, "<i2").astype(np.float32) / 32768
for s in range(len(x)//8000):
    print(f"{s:3d}s  {np.sqrt((x[s*8000:(s+1)*8000]**2).mean()):.3f}")
PY
```

에너지가 급상승하거나 골짜기 뒤 반등하는 지점이 곡이 실제로 꺾이는 곳이다.
막 길이 합이 음원 길이와 정확히 맞아야 한다. 렌더 시 `--total-ms`로 강제한다.

### 2. SRT를 쓴다

가사를 4~5초 단위로 끊어 `assets/whiteboard/<프로젝트>/<이름>.srt`에 넣는다.
줄 단위 타임코드는 정확할 필요가 없다 — 가사를 화면에 띄우지 않으므로 결과에
영향이 없다. **막 경계만 측정값이어야 한다.**

### 3. 선화를 막마다 1장 생성한다 → **멈추고 확인받는다**

위 시각 규범을 전부 프롬프트에 넣는다. 막마다 하나의 핵심 의미만 담는다.
저장 위치는 `assets/whiteboard/<프로젝트>/scene-01-<이름>.png`.

**먼저 이미지를 직접 생성할 수 있는지 확인한다.** 계정에 붙은 이미지 생성
커넥터(Higgsfield·Abocado·Gamma 등)나 이미지 생성 스킬이 있으면 그걸 쓴다.
이 경로에서는 사용자가 곡만 주면 되고, 이 단계도 자동으로 지나간다.
두 완성 사례(Dreamers·Shine)가 실제로 이렇게 만들어졌다.

**직접 생성할 수단이 없으면 프롬프트를 사용자에게 넘기고 기다린다.**

- 막 개수만큼 프롬프트를 **복붙 가능한 형태로 통째로** 준다. 요약하지 않는다.
- 저장할 파일 경로와 이름을 정확히 알려준다.
- 사용자가 외부 도구(ChatGPT·Nano Banana·Midjourney 등)에서 PNG를 만들어
  폴더에 넣을 때까지 기다린다. 그동안 다음 단계로 넘어가지 않는다.
- PNG가 들어오면 크기와 종이 균일도를 확인한다(아래 검사 명령).

어느 경로든, 선화를 보여주고 **멈춘다.** 사용자가 확인하기 전에 annotation을
만들지 않는다.

받은 선화 검사:

```bash
PYTHONUTF8=1 <ENV_PY> - <<'PY'
import cv2, glob
for p in sorted(glob.glob("assets/whiteboard/<프로젝트>/scene-*.png")):
    im = cv2.imread(p); h, w = im.shape[:2]; k = 60
    sd = max(float(c.reshape(-1,3).std(axis=0).mean()) for c in
             (im[:k,:k], im[:k,w-k:], im[h-k:,:k], im[h-k:,w-k:]))
    print(f"{w}x{h}  모서리 표준편차 {sd:5.2f}  "
          f"{'OK' if w>=2560 and sd<1.5 else '확인 필요'}  {p.split('/')[-1]}")
PY
```

긴 변이 2560 미만이면 켄번즈 확대 여유가 없고, 모서리 표준편차가 1.5를 넘으면
종이 얼룩이 마지막 프레임에 한꺼번에 나타난다(시각 규범의 "얼룩 없는 균일한 종이"
문구가 프롬프트에 빠졌다는 뜻이다).

### 4. annotation.json을 쓴다

먼저 **해당 막의 가사를 읽고, 실제로 이미지를 보고, 원본 픽셀 크기를 구한다.**
가사만 보고 추측하거나 화면 좌표 순서로 기계적으로 정렬하면 안 된다.

가사의 사건을 뽑아내고, 이미지에서 보이는 주체를 그 사건에 대응시켜
**장면 바탕 → 핵심 인물·물체 → 동작·변화 → 반응·결과** 순서로 배치한다.

`scene-01-<이름>.png` ↔ `scene-01-<이름>.annotation.json` — **이름이 같아야 한다.**

```json
{
  "sceneId": "scene-01",
  "canvas": { "width": 2560, "height": 1440 },
  "storyBasis": "이 막 가사의 사건 요약",
  "sceneDurationMs": 34000,
  "elements": [
    {
      "id": "ground",
      "label": "지면과 오르막",
      "sequence": 1,
      "narrativeRole": "장면 바탕",
      "subtitle": "Together we rise, with passion inside",
      "type": "structure",
      "region": { "x": 20, "y": 700, "width": 2500, "height": 700 },
      "reveal": {
        "direction": "left_to_right",
        "startMs": 300,
        "durationMs": 5000,
        "maskPaddingPx": 22,
        "protectedRegions": []
      },
      "handPath": { "start": [40, 1050], "end": [2500, 1050], "easing": "easeInOut" }
    }
  ]
}
```

지켜야 하는 것:

- `canvas`는 **원본 PNG 픽셀 크기와 정확히 같다.** 백분율·비율·추정 좌표 금지.
- 모든 `region`은 캔버스 안의 정수 픽셀.
- `sequence`는 1부터 연속.
- **펜은 하나다.** `startMs`가 겹치지 않게 직렬로 놓는다. 다음 영역은 이전 영역의
  `startMs + durationMs`(+ 숨돌릴 100~300ms)에서 시작한다.
- 영역의 실제 허용 마스크 = `region` − (뒤 순서 영역들의 `region`) − `protectedRegions`.
  서로 겹치는 주체는 **앞 순서 영역의 `protectedRegions`에 뒤 주체 영역을 적어**
  미리 새어나오지 않게 막는다.
- `direction`과 `handPath`는 **예뷰대 전용**이다. 실제 필적에 영향을 주지 않는다.
- `durationMs`는 영역 안에서 `ink:color = 2:1`로 쪼개진다.
  초기 추정값은 그리는 거리 ÷ 150픽셀/초.

작성 직후 예뷰대를 열어 해당 폴더를 불러온다.

```bash
start assets/preview.html          # Windows
open assets/preview.html           # macOS
```

### 5. 영역 검사도를 낸다 → **멈추고 확인받는다**

```bash
PYTHONUTF8=1 python scripts/render_annotation_preview.py \
  <선화.png> <annotation.json> <검사도.png>
```

번호·방향이 가사 순서와 맞는지, 모든 영역이 캔버스 안인지, 겹치는 주체가
`protectedRegions`로 보호됐는지 확인한다. 검사도를 보여주고 **멈춘다.**

### 6. 예뷰대에서 조정한다

Chrome·Edge로 `assets/preview.html`을 열고 "폴더 열기"로 장면 폴더를 고른다.
영역 사각형을 끌어 `region`을, 오른쪽 패널에서 시작·종료(ms)와 자막을,
모듈 목록을 끌어 순서(`sequence` 자동 재배열)를 고친다.
저장하면 원본 `.annotation.json`에 다시 쓴다.

파일 쓰기는 File System Access API가 필요하다(Chrome·Edge). 다른 브라우저는
다운로드 후 수동으로 덮어쓴다.

### 7. 막별로 렌더한다

```bash
PYTHONUTF8=1 <ENV_PY> scripts/render_stream_whiteboard.py \
  assets/whiteboard/<프로젝트>/scene-01-<이름>.png \
  assets/whiteboard/<프로젝트>/scene-01-<이름>.annotation.json \
  assets/whiteboard/<프로젝트>/scene-01-<이름>-whiteboard.mp4 \
  assets/drawing-hand-clean.png \
  --cap-long-edge 2560 --fps 30 --total-ms 34000
```

`--cap-long-edge 2560`을 **빼면 안 된다.** 빼면 출력이 1080px로 줄고, 손이
절대 픽셀(493px) 크기여서 프레임 높이의 82%를 덮는다.

`--fps 30`도 **빼면 안 된다.** 렌더러 기본값은 60이다. 60fps로 렌더하면
프레임 수가 두 배가 되어 8단계 켄번즈 스크립트의 `N` 값과 어긋나고,
카메라 무빙이 영상 절반에서 끝난다.

`--total-ms`는 1단계에서 측정한 막 길이다. 2560px·30fps에서 막당 2분 30초~3분 30초 걸린다.
말미에 `OUTPUT=<경로>`가 나오면 성공이다. 나온 프레임 수를 기록해 둔다 —
8단계에서 필요하다.

### 8. 카메라 무빙을 얹는다

렌더러에는 카메라가 없다. 무음 MP4에 ffmpeg로 별도 패스를 얹는다.
`assets/whiteboard/mayclass-dreamers/kenburns_and_mux.sh`를 복사해 고쳐 쓴다.

곡 에너지에 맞춰 막마다 다르게 간다. 잔잔한 편곡에 큰 무브를 얹으면 화면이
곡보다 앞서 나간다.

| 막 | 무브 | 이유 |
| --- | --- | --- |
| 첫 막 | 줌인 1.00 → 1.12, 중심 살짝 위 | 조용히 다가가기 |
| 중간 막 | 좌→우 슬로우 팬 + 1.05 → 1.15 | 빌드업이 밀어 올림 |
| 마지막 막 | 풀백 1.18 → 1.00 | 전체가 드러나며 끝맺음 |

두 가지를 반드시 지킨다.

- **16:9를 먼저 확보한다**: `crop=2524:1420:18:0`. 안 하면 가로가 1.4% 눌린다.
- **팬을 이동 최대치까지 밀지 않는다.** `x='(iw-iw/zoom)*(on/(N-1))'`로 쓰면
  마지막 프레임에서 최대치까지 가고 인물이 반쯤 잘린다. 계수를 곱해 여유를 남긴다.

  ```
  끝 오프셋 = (크롭폭 - 크롭폭/최대줌) × 계수
  조건: 끝 오프셋 <= 가장 왼쪽 요소의 x
        끝 오프셋 + 크롭폭/최대줌 >= 가장 오른쪽 요소의 x + 폭
  ```

  계수는 눈대중하지 말고 계산한다. 실측 사례에서 100%는 잘렸고, 75%는 여유 7px로
  아슬아슬했고, 50%가 80px 여유로 안전했다. 원본 좌표를 렌더 좌표로 옮길 때
  **해상도 스케일과 16:9 크롭 오프셋을 함께 적용**해야 값이 맞는다.

### 9. 합치고 먹싱한다

`merge_scenes.py`는 **영상만 이어붙인다. 오디오 처리가 없다.**

```bash
ffmpeg -y -f concat -safe 0 -i _concat.txt -c copy _merged.mp4
ffmpeg -y -i _merged.mp4 -i <음원.mp3> \
       -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest final.mp4
```

막별 MP4 길이의 합이 음원 길이와 맞아야 한다.

## 검수

- 첫 프레임이 깨끗한 미색 종이. 선이 미리 새어나오지 않는다.
- `canvas`가 원본 PNG 픽셀 크기와 일치. 모든 `region`이 캔버스 안의 정수 좌표.
- 중간 프레임에서 아직 시작 안 한 영역과 보호구역이 보이지 않는다.
- 펜 끝이 지금 그려지는 필적에 붙어 있다.
- 막마다 끝에서 최소 0.5초 완성된 그림이 머문다.
- 켄번즈 후 잘린 요소가 없다. 특히 풀백 시작 프레임.
- 최종 길이가 음원과 맞고, 막 전환이 곡의 전환과 어긋나지 않는다.
- **화면 어디에도 글자가 없다.**
- 펜대에 원저자 채널명이 없다(`drawing-hand-clean.png`를 썼는지).

## 알려진 제약

- 카메라가 없어 무빙은 전부 후처리다. 3D 이동·회전은 못 한다.
- `reveal.direction`·`handPath`는 예뷰대 전용이다.
- 어떤 영역에도 속하지 않은 픽셀은 마지막 프레임에 한꺼번에 나타난다.
  선화 프롬프트에 "얼룩 없는 균일한 종이"를 명시해 애초에 막는다.
  이미 생성된 이미지는 플랫필드 보정으로 배경을 평탄화한다
  (1/8 축소 → 강한 미디언 블러 → 확대 = 배경장, `원본 - 배경장 + 목표색`,
  밝고 저채도인 픽셀만 목표색으로 스냅).

더 자세한 근거와 측정값은 `docs/함정노트.md`에 있다.
